# 分支预测完全指南：从一次数据重排优化说起

> 一条线索串起四个问题：一个真实的优化案例 → 预测器为什么只能是硬件 → 预测算法如何演进 → ARM 与 x86 各家的具体实现。

---

## 第一部分：一个案例 —— 稳定划分让分支变得可预测

### 题目背景

对同一个包含 100,000 个整数的数组，重复回答同一个阈值查询 100 次：

```c
#define N 100000
#define REPEATS 100

long solve(int *arr, int n) {
    long total = 0;
    for (int r = 0; r < REPEATS; r++) {
        for (int i = 0; i < n; i++) {
            if (arr[i] > 128) {          // ← 热分支，随机数据上接近 50/50
                total += arr[i];
            }
        }
    }
    return total;
}
```

约束：允许做一次预处理、必须精确保留所有数值、不准用 SIMD / 多线程、输出须与参考实现严格一致。

指标目标：**Branch MPKI < 1.5，IPC > 2.6**。

### 解法：一次 O(n) 稳定划分

```c
long solve(int *arr, int n) {
    int *tmp = (int*)malloc((size_t)n * sizeof(int));
    int left = 0, right = 0;

    for (int i = 0; i < n; i++)
        if (arr[i] <= 128) tmp[left++] = arr[i];   // 第一趟：全部 ≤128 搬到前面

    right = left;
    for (int i = 0; i < n; i++)
        if (arr[i] > 128) tmp[right++] = arr[i];   // 第二趟：全部 >128 接到后面

    long total = 0;
    for (int r = 0; r < REPEATS; r++) {            // 主体循环完全不动
        for (int i = 0; i < n; i++) {
            if (tmp[i] > 128) total += tmp[i];
        }
    }
    free(tmp);
    return total;
}
```

注意关键点：**优化全部发生在循环之外**。主体循环一行没改，改的只是喂给它的数据。

### 为什么有效：本质是降低序列的熵

换个视角看就很清楚 —— **分支结果序列的熵决定了可预测性的上限**：

| 数据排列 | 分支结果序列 | 描述这段序列需要多少信息 |
|---|---|---|
| 随机顺序 | `F T F T T F F T F T ...` | 不可压缩，1 bit/元素 |
| 稳定划分后 | `FFFF...F` + `TTTT...T` | 只需记 **1 个翻转点**，O(1) |

随机数据的分支序列是 iid 伯努利，熵最大。**没有任何预测器能在 iid 50/50（即无偏 p=0.5）上超过 50% 命中率** —— 所谓"历史位被冲刷"只是表象，真相是：可预测性来自序列的自相关性，而随机数据没有自相关性。
>
> 注意这个结论的前提是 p=0.5（本例阈值 128 对随机数据接近这个比例）。如果 iid 但有偏（比如 p=0.9），静态预测器"永远猜多数类"就能轻松达到 90% 命中率——"iid"本身不等于"不可预测"，"无偏"才是关键。

### 量化差距

设每次迭代约 5 条指令，误预测代价约 15–20 cycles：

| | Baseline | 稳定划分后 |
|---|---|---|
| 分支执行次数 | 1000 万 | 1000 万 |
| 误预测率 | ≈ 50% | 每轮 ~4 次 |
| 误预测总数 | ~500 万 | ~400 |
| 浪费周期 | ~7500 万（≈25ms @3GHz） | ~6000（可忽略） |
| **Branch MPKI** | **~100** | **~0.008** |

MPKI 目标 < 1.5，实测能到 0.01 量级，有两个数量级的余量。

> **为什么是"每轮 4 次"而不是 2 次？**
> 划分后每轮有**两次翻转**：中点处 `F→T`，以及下一轮回到开头 `T→F`。而 2-bit 计数器翻转需要**连续错两次**（强→弱→反向弱），所以每次翻转吃 2 次误预测 → 每轮 4 次。这正是 2-bit 滞后机制的"成本"：用"多错一次"换"抗噪声"。

### 三个值得多想一层的点

**1. "稳定（stable）"其实是顺带的，不是必需的。**
求和是整数加法，满足交换律，只要**元素多重集不变**结果就一致。段内相对顺序保不保留无所谓 —— 你需要的是"两段"这个性质，不是"段内有序"。这也解释了为什么不需要 O(n log n) 的排序。

**2. 预处理自己也有随机分支。**
两趟收集里 `arr[i] <= 128` / `arr[i] > 128` 面对的还是随机数据，各自约 5 万次误预测 ≈ 150 万 cycle。但它是 **O(n) 一次性的**，被 100 轮摊薄 → 占比 < 2%。如果只有 1 轮扫描，这就是净亏损。

**3. 真要追求稳健，无分支（branchless）更保险。**
`total += (arr[i] > 128) ? arr[i] : 0` 编译成 `cmov`，MPKI 直接归零，且**不依赖数据分布**。数据重排的收益完全建立在"数据恰好可重排 + 查询重复多次 + 阈值固定"三个前提上，任何一个不成立就会退化。

### 速记

- 优化的本质不是"让预测器变强"，而是**把高熵序列改造成低熵序列** —— 信息论上限变了
- 划分后只剩翻转点处 ~2 次/轮的误预测（2-bit 滞后 ×2）
- 前提：**一次整理、多次查询**；单次扫描别照搬

## 第二部分：预测器是 CPU 硬件实现的吗？

### 是，纯硬件，在前端

不是固件、不是微码 —— 是实打实的电路 + 片上 SRAM，位于 CPU 核心的**取指前端（frontend）**。

**为什么只能是硬件？** 流水线的取指阶段有个鸡生蛋问题：**取指时你甚至还不知道这条指令是不是分支**。指令还没译码，不知道类型，更不知道目标地址。但流水线每个周期都要新的指令地址，不可能停下来等译码结果。所以必须在取指阶段就用极短延迟（1–2 周期）给出两个答案：

1. **跳不跳**（方向）
2. **跳到哪**（目标）

软件在这件事上完全插不上手 —— 等软件能执行的时候，预测已经做完了。这也是历史上 x86 加过的分支提示前缀（Pentium 4 的 `2E`/`3E`）后来被废弃的原因：软件提示来得太晚且太粗。

### 硬件部件分工

| 部件 | 解决的问题 | 存的是什么 |
|---|---|---|
| **BTB**（Branch Target Buffer） | 这个 PC 是分支吗？跳到哪？ | 分支 PC → 目标地址 |
| **方向预测器**（BHR + PHT / TAGE） | 这次跳不跳？ | 历史寄存器 + 饱和计数器表 |
| **RAS**（Return Address Stack） | 函数返回跳回哪 | 调用时压入的返回地址，16–52 项 |
| **ITTAGE / 间接预测器** | 虚调用、switch 表跳到哪 | 长历史索引的目标地址表 |
| **Loop predictor** | 计数循环还剩几次 | 迭代计数 |

存储都是**核心内的 SRAM**，不进内存、不进 L1/L2 cache。原因很直接：BTB/PHT 的访问延迟必须压在 1–2 周期，走 cache 就太慢了。代价是容量受限 —— L1 BTB 通常几百到几千项，PHT 几万项。

### 误预测的代价也是硬件决定的

预测错了，后端要把乱序执行的所有推测状态回滚到 checkpoint，前端从正确地址重新取指。代价大致 = **流水线深度的一部分**：

- 早期 5 级流水线：~5 周期
- 现代 15–20 级、4–6 发射：~15–20 周期，宽后端下机会成本更高

流水线越深越宽，误预测越贵 —— 这是为什么"宽发射 OoO + 激进预测"走到今天，分支预测准确率反而成了 IPC 的关键瓶颈。

### 那软件侧还能做什么

既然预测算法是硬件写死、改不了的，软件能影响的只有**输入给它的序列**：

**1. 降低结果序列的熵** —— 就是第一部分做的事。这是唯一能真正提高动态预测命中率的软件手段。

**2. 调整代码布局**（`likely()` / `unlikely()` / PGO）
这个经常被误解：它们**不会**给硬件传"请预测跳转"的提示（x86 上没这个接口）。真正作用是让编译器：
- 把热路径排成 fall-through（顺序执行，少一次跳转）
- 把冷代码块挪走，改善 icache 局部性
- 减少 BTB 压力

另外硬件对 **BTB 未命中**有静态 fallback 规则（通常向后跳预测 taken、向前跳预测 not taken，正好对循环友好），代码布局会影响这个规则帮不帮得上忙。

**3. 直接消灭分支** —— `cmov` / `setcc` / 算术掩码。MPKI 直接归零，代价是两边都要算，只在分支高度不可预测时才划算。

## 第三部分：预测算法全景

所有分支预测算法在干同一件事：**从历史里找模式，用模式猜未来**。区别只在两个维度 —— **用什么做历史（特征）**，**怎么从历史推出结果（模型）**。这个演进过程本质上就是一段"特征工程 + 模型升级"的历史，和机器学习完全同构。

### 总览

| 算法 | 特征（历史） | 模型 | 解决了什么 | 遗留问题 |
|---|---|---|---|---|
| 静态 | 无 | 固定规则 | 兜底 | 准确率低 |
| 1-bit | 上次结果 | 照抄 | 有历史了 | 循环边界错 2 次 |
| 2-bit bimodal | 自身倾向 | 饱和计数器 | 抗单次噪声 | 抓不住周期模式 |
| 两级局部 | 本分支最近 N 次 | BHR 索引 PHT | 周期模式 | 抓不住分支间相关 |
| gshare / 全局 | 所有分支最近 N 次 | PC⊕GHR 哈希 | 分支间相关 | 无关分支噪声 |
| Tournament | 以上全部 | meta 选择器 | 不同分支用不同算法 | 复杂度上升 |
| **TAGE** | 几何级数多长度历史 | 多表取最长匹配 | 上下文长度自适应 | — |
| 感知机 | 长历史位 | 线性加权求和 | 长历史线性相关 | 非线性模式弱 |

### 第一代：从"倾向"到"模式"

#### 2-bit bimodal（Smith, 1981）

```
     taken      taken      taken
  00 ────► 01 ────► 10 ────► 11
Strongly  Weakly    Weakly  Strongly
NotTaken  NotTaken  Taken   Taken
  ◄──────── ◄──────── ◄────────
   not taken  not taken  not taken

   (高位决定预测：00/01 → 不跳，10/11 → 跳)
```

本质是**多数投票**。要改变预测方向**必须连续错两次**，这个滞后机制能扛住偶发噪声 —— 循环退出只误预测 1 次而不是 2 次。

历史是 **per-branch** 的：PHT 用分支指令的 **PC 低位**索引，同一个 `if` 语句有自己的独立计数器槽位（代价是不同分支可能 aliasing 撞到同一槽）。

**致命缺陷**：对 `T F T F T F...` 这种完美周期-2 序列完全无解 —— 总体倾向 50/50，计数器反复震荡，命中率接近 0。

#### 两级自适应预测（Yeh & Patt, 1991）—— 关键飞跃

思路转变：不再存"总倾向"，而是存**"在特定历史上下文下，下一次是什么"**。

```
BHR (Branch History Register)：本分支最近 N 次结果的移位寄存器
       ┌───┬───┬───┬───┐
       │ T │ F │ T │ F │  → 值 = 0b1010
       └───┴───┴───┴───┘
                          ↓ 作为索引
                    ┌───────────┐
                    │    PHT    │  ← 2^4 = 16 个 2-bit 计数器
                    │  [1010] → │  每个历史模式一个独立计数器
                    └───────────┘
```

现在 `...T F` 后面接什么、`...F T` 后面接什么，用的是**不同的计数器**。周期-2 序列 100% 命中。这就是从"无记忆模型"升级到 **N 阶马尔可夫模型**。

### 第二代：全局历史 —— 捕捉分支间的相关性

局部历史的盲区：真实代码里分支是相关的（`if (y > 0)` 只有在 `if (x > 0)` 为 true 时才执行），局部历史看不到这层关系。

**gshare（McFarling, 1993）**：把所有分支最近 N 次结果串成**全局历史寄存器 GHR**，然后：

```
index = PC ⊕ GHR     // XOR 哈希，让 PC 和历史每一位互相扩散，减少表项冲突
```

代价：全局历史里混进大量无关分支的结果，是种噪声。有些分支用局部历史更好，有些用全局更好 —— 直接导致下一代。

### 第三代：组合与自适应

#### Tournament（竞赛）预测器

既然没有单一算法通吃，就**都跑，再选**。用 meta-predictor（又一张 2-bit 表）记录"在这个分支上最近是局部赢还是全局赢"。Alpha 21264 的经典实现即此结构 —— 这是**集成学习**思维在硬件上的胜利。

#### TAGE（Seznec, 2006）—— 现代主流

核心洞察：**不同分支需要的历史长度差别巨大**。那就多张表，历史长度按几何级数增长：

```
T0: 基础表（bimodal，无历史）
T1: 历史长度 4     ┐
T2: 历史长度 8     │
T3: 历史长度 16    ├─ 每张表带 tag
T4: 历史长度 32    │
...                │
Tn: 历史长度 ~300  ┘

预测时：所有表并行查，取【tag 匹配 + 历史最长】的那个表的结果
```

哲学很优雅：**优先信任最长可用上下文**。

配套精妙机制：
- **altpred**：次长匹配表的结果，主预测置信度低时备用
- **useful counter**：记录表项是否真的有用，决定替换策略
- **TAGE-SC-L**：TAGE + Statistical Corrector + Loop predictor（CBP 竞赛标准答案结构）

### 另一条路：感知机预测器（Jiménez & Lin, 2001）

TAGE 是"查表派"巅峰，感知机走"计算派"：

```
每个分支一组权重：w[0], w[1], ..., w[n]   （有符号整数）
历史位：h[i] ∈ {+1 (taken), -1 (not taken)}

y = w[0] + Σ w[i] × h[i]
预测：y >= 0 → taken

训练（每次实际结果出来后）：
if (预测错 或 |y| < 阈值θ)
    w[i] += t × h[i]     // t = 实际结果(+1/-1)
```

这是一个**单层神经网络**，用在线梯度下降训练。

**优势**：
- 能利用**很长的历史**（几百位），加法树延迟可控
- 面积效率比查表高得多 —— TAGE 的表随历史长度指数增长，感知机是线性的

**弱点**：学不了 XOR 这类非线性模式。

### 一个容易被忽略的工程难点：历史寄存器的投机更新

前面的模型都隐含一个假设——"结果出来后再更新历史"。但现代 CPU 是乱序、深度流水线执行的：**取指阶段就要用 GHR/PHR 去查表**，可分支还要几十条指令、十几个周期之后才真正 retire、才知道对错。如果老老实实等 retire 才更新历史寄存器，后面几十个已经进流水线的分支全都拿着"过期"的历史查表，预测直接失效。

所以实际做法是**投机更新（speculative update）**：一旦做出预测，立刻按预测结果把历史寄存器往前推一位，让后续取指立刻用上"最新"的历史；同时保留足够的 checkpoint，一旦分支最终被判定预测错误，把历史寄存器和其他相关状态一起回滚到误预测点。这跟乱序执行本身"先猜后验、错了就回滚"的哲学是同一套机制在前端的延伸，只是这里回滚的是"历史"而不是寄存器堆。这也是为什么误预测代价里除了流水线冲刷，还隐含着历史寄存器状态的重建开销。

### 特殊兵种：Loop Predictor

固定次数循环是最常见也最"机械"的模式（连续 9999 次 taken，然后 1 次 not taken）。通用预测器能学会，但要用掉大量表项，且最后一次迭代的翻转会污染历史。所以现代 CPU 单独放一个**专用循环预测器** —— 典型的**领域专用优化**。

### 统一的视角

```
预测 = 模型(特征)
特征 = 历史（自身 / 全局 / 多长度 / 分支间相关）
模型 = 查表 / 线性加权 / 竞赛选择
更新 = 在线学习（每次结果出来后修正状态）
```

演进方向一清二楚：**特征从"无"到"上次"到"N 位"到"多长度自适应"；模型从"固定规则"到"计数器"到"多层表"到"线性分类器"**。

### 为什么不用更聪明的算法？

| 约束 | 量级 | 后果 |
|---|---|---|
| **延迟** | 1–2 周期出结果 | 不能迭代、不能串行查表、神经网络不能太深 |
| **面积** | 核心内 SRAM 有限 | 表不能太大，历史不能存太多 |
| **功耗** | 每周期都要查 | 核心功耗大头之一 |
| **在线性** | 必须 streaming 更新 | 不能离线训练、不能 batch |

有趣现象：**分支预测是计算机体系结构里最早、最成功应用机器学习的领域之一**（感知机预测器 2001 年就提出），但模型始终停留在最浅的一层 —— 不是不想深，是延迟预算不允许。

## 第四部分：ARM 与 x86 各家的具体实现

> ⚠️ **重要前提**：**分支预测器和指令集架构（ISA）没有关系，只和微架构实现有关。** ARM 和 x86 在"预测算法"上不存在阵营差异 —— 今天两边的高性能核都收敛到了 TAGE 家族。真正有区别的是**厂商的设计取舍**。
>
> 另外：**没有任何一家厂商公开过完整的预测器设计**。下文 Intel / Apple / 高通的具体数字来自学术界用微基准测试逆向工程的结果（Spectre 之后 Google Zero 对 Haswell 的逆向，以及后续的 Half&Half、清华团队对 Apple/高通的工作）；ARM 官方 TRM 只列组件，从不说算法。凡涉及具体数字，请当作"高精度推测"而非官方规格。

### Intel（x86）：TAGE，一路拉长历史

逆向结果相当一致：**Haswell 到 Alder Lake 用了同一套 CBP 设计，主要改动是不断加长历史** [citation:36]。

| 参数 | Haswell / Skylake / Cascade Lake | Ice Lake / Tiger Lake / Alder Lake |
|---|---|---|
| 历史寄存器 | PHR **93×2 bit** | PHR **194×2 bit** |
| TAGE 表数 | 3 个 PHT | 3 个 PHT |
| 相联度 | 4-way | 4-way |
| 索引函数 | 8 位折叠 PHR 位 + **仅 1 位 PC** | 同 |
| 基础预测器 | PC[12:0] 索引 | 同 |

几个有意思的细节：

- **历史只记 taken 的分支** —— not-taken 不进历史。这是"路径历史（PHR）"而非"结果历史（GHR）"的典型特征，每个 taken 分支左移 2 位 [citation:36]。
- **索引里只用了 1 位 PC**，其余 PC 位全去做 tag。相当激进：PC 区分度几乎全靠 tag 匹配兜底，好处是索引函数极简、延迟低 [citation:36]。
- 对比之下 Apple/高通各用了 6 张表 —— **Intel 走"少表 + 超长历史"，Apple/高通走"多表 + 中等历史"** [citation:26]。

### AMD（x86）：感知机 + TAGE 的双层，业界独一份

AMD 是唯一公开承认用**感知机（perceptron）**的厂商 [citation:34]。

```
Zen 1:  L1 = hashed perceptron（快、低精度）
Zen 2+: L1 = hashed perceptron   ← 1 周期出结果
        L2 = TAGE                ← 慢、高精度，校验并覆盖 L1
```

- **L1 感知机**：用分支地址取一个权重向量，和 GHR 历史位做点积，符号决定 taken/not-taken。相比 gshare 约提升 10% 准确率，最大优势是**硬件开销随历史长度线性增长** [citation:27][citation:37]。
- **L2 TAGE**：几何级数长度的多张表，处理感知机搞不定的长程模式 [citation:30][citation:37]。

Agner Fog 的实测很能说明这套东西的能力边界 [citation:41]：

| | 能完美预测的循环次数上限 |
|---|---|
| Zen 1 / 2 | ~12 |
| Zen 3 / 4 | ~64 |
| Zen 5 | ~128 |

而且"周期性重复模式似乎没有长度上限" —— 这正是感知机擅长长历史的体现。

**Zen 5 的前端改动最大** [citation:38][citation:35]：

- **L1 BTB 1.5K → 16K 项**（10 倍），采用 **victim cache** 结构（L1 淘汰的项进 L2 8K），合计可追踪约 **24K 个分支目标**
- 导入 **2-ahead 预测器**，配合 Zen 4 已有的"每周期预测 2 个 taken 分支"
- TAGE 表扩容，返回栈 32 → 52 项

### ARM 公版（Cortex-X / Neoverse）：官方只给组件清单

ARM 的 TRM 永远是这样一段话 —— BTB + 方向预测器 + 返回栈 + 静态预测器 + 间接分支预测器，**算法一个字不提** [citation:1][citation:3]。

从 ARM 对外宣传的代际改动能拼出大致轮廓：

| 微架构 | 公开的前端改动 |
|---|---|
| Cortex-X3 | L0 BTB 容量 ×10，L1+L2 BTB +50%，新增**专用间接分支预测器**，返回栈翻倍至 32 [citation:9] |
| **Neoverse V2** | 明确写了 **"8-table TAGE direction predictor with staged output"** —— ARM 罕见的算法级公开 [citation:9] |
| Neoverse V2 | nanoBTB ×10，主 BTB 拆两级，TAGE 表 ×2 且改 2-way，历史更长，每周期 2 分支 [citation:9] |
| Neoverse V1 | 6× nano BTB（96 项），8K 主 BTB，BTB miss 误预测降低达 90% [citation:15] |
| Cortex-X925 | 预测指令窗口 ×2，取指带宽 ×2 [citation:9] |

**"staged output"（分级输出）很关键**：TAGE 查表有延迟，ARM 让短历史表先出结果、长历史表稍后修正，在精度和延迟之间做流水线化折中。

### Apple / 高通（ARM 指令集，自研微架构）：6 表 TAGE，80KB

清华团队的逆向给出了迄今最详细的 ARM 侧数字 [citation:26][citation:20]：

| | Apple Firestorm (M1) | Qualcomm Oryon |
|---|---|---|
| TAGE 表数 | **6** | **6** |
| 各表历史长度 | 100 / 57 / 28 / 18 / 11 / 6 | 100 / 52 / 32 / 14 / 7 / 4 |
| 相联度 | 4-way | 4-way |
| 索引用到的 PC 位 | PC[6], PC[9] | PC[6], PC[7] |
| 历史寄存器 | PHRB(28) + PHRT(100) | PHRB(32) + PHRT(100) |
| 总预算 | 80 KB | 80 KB（官方数字，与推算完全吻合） |

两个值得注意的设计选择：

1. **双历史寄存器**：`PHRB` 记录分支指令自身 PC 位（B[5:2]），`PHRT` 记录跳转目标地址位（T[31:2]），各自左移异或更新 [citation:26]。与 Apple 专利 US12159142B1 描述的 "path_hist + global_hist" 结构吻合。Intel 只有一个 PHR。
2. **80KB 的预测器存储**已经达到 Firestorm 128KB L1 数据缓存的六成以上 —— 现代高性能核对预测的投入已经夸张到这个程度。

### 横向对比

| 维度 | Intel | AMD | ARM 公版 | Apple / 高通 |
|---|---|---|---|---|
| 方向预测 | TAGE（3 表） | 感知机 + TAGE | TAGE（V2 是 8 表） | TAGE（6 表） |
| 历史长度 | 93 → **194** taken 分支 | 未公开，实测极长 | 未公开 | **100** |
| 历史类型 | 单 PHR | 感知机吃 GHR | 未公开 | **PHRB + PHRT 双路** |
| L1 BTB | 小（百项级）+ 大 L2/L3 | **16K**（Zen 5，victim） | nanoBTB + 两级主 BTB | 1K~3K L0 + ICache 当末级 |
| 预测带宽 | 1~2 分支/周期 | **2 taken/周期**（Zen 4+） | 2 分支/周期 | 未知 |
| 误预测惩罚 | ~15–20 周期 | 11–18（常见 13） | 未公开 | Oryon 13 周期 [citation:4] |

**真正有意思的分歧在 BTB 而不是算法**：方向预测大家都用 TAGE，但 BTB（目标地址缓存）路线完全分道扬镳 ——

- **AMD**：堆一个 16K 的巨大 L1 BTB，用 victim cache 兜底 [citation:38]
- **Intel**：小 L1 + 深层次的 L2/L3 BTB
- **Apple**：L0 BTB 只有 1K，但**把 L1 指令缓存当末级 BTB 用** —— 非分离式前端取指时顺带做预译码，从 ICache 行里直接拿到分支信息 [citation:18][citation:10]

三条路能达到相近效果，代价分布不同（面积 / 延迟 / 功耗）。

## 收束：回到那个优化案例

这些厂商差异对"稳定划分"优化意味着什么？

**几乎什么都不意味着 —— 这正是好消息。** 无论底层是 Intel 的 3 表 194 位历史、AMD 的感知机、还是 Apple 的 6 表 80KB，它们学的东西本质相同：**历史序列里的自相关**。而随机数据没有自相关，这是信息论层面的结论，与具体实现无关。

具体到你那个循环，重排后的收益来源非常"笨"：序列变成 `FFFF...FTTTT...T`，只需要 TAGE 的**最短那张表**（甚至基础 bimodal 预测器）就能全中。也就是说**你根本没用到 TAGE 的长历史能力** —— 这也解释了为什么实测 MPKI 能低到 0.01 量级：连 2-bit 计数器都够用的模式，任何预测器都不会失手。

唯一会因厂商而异的是**误预测惩罚**：Intel ~15–20 周期、AMD ~13、Oryon 13。基线版本那 500 万次误预测，在不同机器上的绝对耗时会有 ±30% 浮动，但"从百万级降到百级"这个数量级差异在哪都成立。

### 一句话总结

> 你没法改预测器的模型，但你可以改喂给它的数据 —— 这正是软件侧唯一能做的事。
