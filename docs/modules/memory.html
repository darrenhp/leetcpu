内存层次与延迟隐藏

容忍 CPU 与内存之间的速度鸿沟。

即便缓存用得再好，总有些负载必须访问主存。

关键认知是：延迟不等于带宽 —— 只要能同时发出足够多的独立访存，内存控制器就能把它们重叠起来，在高延迟下依然获得高吞吐。

这种能力称为内存级并行（MLP）。

概念讲解

延迟 vs 带宽

单次访存延迟约 200 周期看似无法逾越，但内存系统能同时服务十几条请求。

串行等待每次 200 周期，与 16 个请求并行、总耗时仍接近 200 周期，吞吐相差十几倍。

衡量访存性能时，要看"同时在飞行中的请求数"，而不是单次延迟。

硬件预取与软件预取

硬件 stride 预取器能识别固定步长的访问流，但对随机指针完全无能为力。

软件预取用 __builtin_prefetch 提前若干次迭代把地址取入缓存：距离太近来不及、太远又会被挤掉，通常需要按实测调整。

对随机访问，预取的价值在于把"串行等待"变成"批量等待"。

行缓冲与 DRAM 时序

DRAM 内部按行（row）组织，命中已打开的行可以直接读，未命中则要先关闭再激活，代价高得多。

跨超大步长跳跃、在多个大数组间来回切换，都会频繁触发行冲突。

把访问按物理页/行聚集，往往比单纯提高局部性更有效。

关键指标

指标怎么读
DRAM 事务数落到主存的访问次数，直接决定带宽压力。
行缓冲命中率DRAM 行缓冲命中比例，命中率过低说明访问在行之间反复横跳。
LLC 平均失效延迟LLC 失效后平均等待周期，反映预取是否奏效。
动手提示
在 Analysis 的 DRAM 区域查看 Row Buffer Miss 计数，它能揭示你的访问模式对 DRAM 是否友好。
