分支预测

让 CPU 提前猜中程序的下一步。

现代 CPU 采用推测执行：在条件判断真正算出结果之前，就先猜测分支会走哪条路并提前执行。

猜对了，流水线的等待时间被完全隐藏；猜错了，已经执行的几十条指令全部作废、流水线被清空，代价约 10–20 个周期。

消除不可预测分支，是投入产出比最高的优化手段之一。

概念讲解

流水线如何看待一条分支

取指阶段还没等条件码算出来，分支预测器就已经根据历史给出了方向，前端沿着预测路径继续取指。

条件真正解析完成时若发现猜错，从该分支之后进入流水线的所有微指令都要被取消，重排序缓冲（ROB）回滚，前端从正确地址重新取指。

因此分支的代价不在于"执行分支指令"本身，而在于它身后被白白执行又被丢弃的那一段工作。

什么会导致预测失败

数据相关：分支条件依赖刚从内存载入、尚未就绪的值。

随机性：输入在真/假之间接近 50/50 抖动，任何基于历史的预测器都退化为抛硬币。

历史污染：同一个分支被不同调用点以不同规律使用，预测器的历史表被互相干扰。

容量不足：分支数量超过 BTB 或方向预测表容量，条目被反复挤掉。

如何修复

消除分支：用算术与位运算把条件判断改写成无分支表达式（掩码、条件传送、查表）。

让分支变得可预测：先排序或分区，使同一分支在长时间内保持同一方向。

把分支挪出热循环：以循环外的一次判断换取循环内的零判断。

减少分支数量：把多层嵌套 if/else 折叠成一次查表。

关键指标

指标怎么读
分支准确率预测正确的分支占比。目标 ≥ 97%，低于 90% 说明该分支正在严重拖垮前端。
Branch MPKI每千条指令的分支预测失败次数。每次失败约损失 15 个周期，是最直观的分支代价指标。
IPC 分支损失IPC 停顿预算中"分支误预测"那一段，直接量化流水线清空损失了多少发射槽。
动手提示
跑一次代码后打开 Analysis → IPC stall budget，"Branch mispredict" 那根柱子的高度就是被分支清空浪费掉的发射槽。
