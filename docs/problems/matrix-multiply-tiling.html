矩阵乘法：分块与转置

转置 B 消除列访问，再用分块把工作集压进缓存。

原始英文标题：Matrix Multiply — Cache Tiling

题面

计算两个 512×512 行优先 float 矩阵的乘积 C = A × B。

基线实现按行读 A，却按列遍历 B，空间局部性极差并产生大量本可避免的缓存失效。

请用分块、转置或两者结合重写循环嵌套，让内层循环以缓存友好的顺序读取内存。

任务
实现 void solve(float *A, float *B, float *C)，精确计算两个 512×512 行优先矩阵的乘积，同时改善缓存局部性。

约束

  • N = 512（固定）
  • 矩阵为行优先 float
  • 不允许外部库（禁用 BLAS）
  • 不允许多线程
  • 允许 SIMD

示例

输入A、B 为 512×512 行优先 float 矩阵
输出C = A × B，与朴素实现逐位一致（含浮点容差）
说明内层 k 循环中，B[k*N + j] 的相邻迭代地址相差 N×4 = 2048 字节，即每次都换一条缓存行 —— 这正是要消除的访存模式。

优化报告


维度内容


核心瓶颈缓存空间局部性


一句话思路转置 B 消除列访问，再用分块把工作集压进缓存。


报告摘要两步走：先转置 B 让内层循环变连续，再对 i/j/k 三重循环做 64×64×64 分块，让 A、BT、C 的数据块在计算期内留在缓存中被反复复用。





瓶颈定位
内层 C[i*N+j] += A[i*N+k] * B[k*N+j] 中，k 变化时 B[k*N+j] 的地址每次跳 2048 字节 —— 每次访问一条新缓存行，而这条行里只用了 4 个字节。
总访存量看似只有 3 个矩阵 × 1MB，但按行计的访问模式会把有效带宽浪费 16 倍（64 字节行只用 4 字节）。
L1 MPKI 高达数十，IPC 被访存延迟压住。
优化思路
转置：预先构造 BT[j*N+i] = B[i*N+j]，使内层 BT[j*N+k] 沿 k 连续访问，一行 64 字节全部被利用。
分块：把 512×512×512 的迭代空间切成 64×64×64 的块。处理一个块时，A 的一块（64×64×4B=16KB）、BT 的一块（16KB）与 C 的一块（16KB）合计约 48KB，恰好贴近 L1 容量。
块内 k 循环把 C[i][j] 累加到寄存器变量 sum 中，避免每步写回内存。
关键改动
先用 O(N²) 的转置把 B 变成 BT —— 这是一次性成本，被 N³ 的计算完全摊薄。
三层 ii/jj/kk 分块循环（TILE=64）+ 三层块内循环，共六层嵌套。
把 C[i*N+j] 提升到寄存器 sum，块内 k 循环结束后一次性写回。
为什么更快
转置把 B 的缓存行利用率从 4/64 提升到 64/64，等价地把 B 侧的有效带宽提升约 16 倍。
分块让同一块 A 数据被 64 个 j 复用、同一块 BT 被 64 个 i 复用，把 O(N³) 的访存降到接近 O(N³/TILE)。
寄存器累加避免了 C 的重复读写，同时给编译器留出向量化空间。
常见误区
TILE 越大越好？不是。块太大装不进 L1 就会退化，通常要让 3 个块的总量略小于 L1 容量的一半到三分之二。
只转置不分块：能消除列访问，但 A、B 仍会被反复从 L2/LLC 重新读入，收益有限。
忽略边界：512 能被 64 整除，本题无需处理余数；实际工程中必须写清尾块处理。



要点速记
  • 转置消除跨步访问
  • 六层分块循环
  • 寄存器累加 + 末尾一次写回


常见误区与边界条件
  • 分块尺寸需按实际缓存容量调
  • A、BT、C 三块合计不能超过 L1
