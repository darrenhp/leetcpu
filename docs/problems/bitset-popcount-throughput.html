位图统计：用 popcount 硬件替代逐位扫描

64 次移位与掩码，被一条 popcnt 指令取代。

原始英文标题：Bitset Scan — Turn Scalar Loops into Throughput

题面

需要统计一个大位图中所有被置位的比特数。基线对每个 64 位字用标量内层循环逐位检查 64 个位置。

这种做法浪费了大量指令，也没有用上 CPU 专用的 population count 硬件。

请把逐位扫描替换为吞吐更优、能映射到 popcount 指令的实现。

任务
实现 unsigned long long solve(unsigned long long *bits, int words)，返回 words 个 64 位字中被置位比特的总数。

约束

  • words = 65536
  • 不允许多线程
  • 允许使用 __builtin_popcountll 等编译器内建函数
  • 结果必须精确

示例

输入bits = 65536 个 64 位字
输出全部置位比特数
说明逐位扫描每个字要执行 64 轮「移位 + 与 + 加」，而 popcount 指令一条就能完成同样的工作。

优化报告


维度内容


核心瓶颈指令数过多 / 未用专用硬件


一句话思路64 次移位与掩码，被一条 popcnt 指令取代。


报告摘要用 __builtin_popcountll 把每字的 64 次迭代压缩为一条 popcnt 指令，再叠加 4 路展开让多条 popcnt 并行执行。





瓶颈定位
基线每字执行 64 次 (word >> b) & 1 并累加，指令数约为 64 × 4 = 256 条/字。
这些指令还构成一条累加依赖链，导致即便执行单元空闲也无法提速。
总指令数约 65536 × 256 ≈ 1677 万条，是纯粹的执行受限（compute-bound）负载。
优化思路
现代 x86 提供 popcnt 指令，一条指令完成 64 位 population count，编译器内建 __builtin_popcountll 会直接映射到它。
每字指令数从约 256 条降到约 2 条（popcnt + add），理论加速比超过 100 倍。
再叠加 4 路展开：多条 popcnt 之间没有数据相关，可以并行发射。
关键改动
内层 64 次循环整体删除，改为直接调用 __builtin_popcountll(bits[i])。
主循环 4 路展开，四个结果依次累加到 total。
尾部循环处理 words % 4 的余数。
为什么更快
指令数下降两个数量级，前端不再成为瓶颈，退休指令数大幅减少。
popcnt 在部分微架构上有 3 周期延迟，但由于各字之间彼此独立，多字并行可以把它完全掩盖。
IPC 提升到 3.8 以上：此时瓶颈已从"执行指令"转移到"取指与访存"。
常见误区
手写位运算技巧（如 SWAR）未必更快：编译器识别 __builtin_popcountll 会直接生成硬件指令，手写版本反而可能阻止这种识别。
误以为 popcnt 在所有 CPU 上都快：部分老架构上是微码实现，需实测。
忽略 -mpopcnt 编译选项：老编译器可能需要显式开启才能生成该指令，否则会退化为库函数调用。



要点速记
  • 用硬件 popcnt 替代逐位循环
  • 指令数下降两个数量级
  • 4 路展开掩盖指令延迟


常见误区与边界条件
  • 手写 SWAR 可能阻止编译器识别
  • 需确认目标架构支持 popcnt
