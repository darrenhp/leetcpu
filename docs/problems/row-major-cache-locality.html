二维网格求和：修正列优先遍历

步长 8KB 的访问模式 —— 改成行优先，再加 64×64 分块。

原始英文标题：2D Grid Sum — Fix Column-First Access Order

题面

对一个大型行优先二维网格中的所有值求和。基线按列优先遍历：外层沿列（x）推进，内层沿行（y）下移。

由于数组按行优先存储，内层循环的相邻迭代会跳过整整一行的宽度 —— 2048 个整数，即 8KB。

每一步都落在一条冷缓存行上，于是内层循环几乎总在等待内存。

任务
实现 long solve(int *grid, int n)，返回 n×n 行优先整数网格的精确和，并以缓存友好的顺序遍历内存。

约束

  • n = 2048（评测中固定）
  • grid 行优先存储：元素 [y][x] 位于 grid[y*n + x]
  • 结果必须精确
  • 不允许多线程
  • 允许 SIMD

示例

输入2048×2048 行优先 int 网格（16MB）
输出全部元素之和
说明每次跨 8KB 跳跃还会跨页，因此 TLB 压力同样很大；改成行优先后两个问题一起解决。

优化报告


维度内容


核心瓶颈列优先跨步访问


一句话思路步长 8KB 的访问模式 —— 改成行优先，再加 64×64 分块。


报告摘要先交换循环顺序让内层沿行连续推进，再叠加 64×64 分块，使一次处理的行段工作集稳定落在 L1 中。





瓶颈定位
内层 sum += grid[y*n + x]，y 变化时地址跳 2048×4 = 8192 字节。
整个网格 16MB，远超 L2/LLC 可容纳范围；每次访问拉入一条 64 字节缓存行却只用 4 字节。
8KB 的跨步同时跨越页边界，导致 dTLB 也持续未命中。
优化思路
循环交换：把 x 循环放内层，使相邻访问地址只差 4 字节，缓存行利用率 100%。
分块：即使行优先，一次扫完整行（2048×4 = 8KB）后这些数据也不会再被用到，无复用可言；但分块能让 64×64 的块（16KB）在处理期间驻留 L1，配合多累加器可获得更好的流式吞吐。
行指针外提：int *row = grid + y*n 提到行循环外，内层只做 row[x]。
关键改动
外层 y0 与 x0 均以 TILE=64 步进，内层按行优先顺序遍历块内元素。
用 y1/x1 处理不能整除的尾块。
行首指针 row 在行循环内计算一次。
为什么更快
循环交换是主要收益：缓存行利用率从 1/16 提升到 100%，等效访存量降为 1/16，且硬件预取器开始生效。
分块在这里是次要收益 —— 纯求和没有数据复用，分块主要作用是让访问在物理页上更聚集、减轻 TLB 压力。
诚实地说：对一次性全量求和，仅做循环交换就已解决绝大部分问题，分块属于锦上添花。
常见误区
以为分块必然带来巨大提升：没有数据复用的场景（如本题的纯求和）中，分块收益远小于 stencil/矩阵乘。
忽略 TLB：16MB 工作集在 4KB 页下需要 4096 个页表项，远超典型 L1 dTLB 容量，这往往是残留瓶颈。
块大小拍脑袋：64×64 ints = 16KB，是 32KB L1 下的稳妥选择；换成 128 就会溢出。



要点速记
  • 循环交换是核心收益
  • 行指针外提
  • 分块主要缓解 TLB 压力


常见误区与边界条件
  • 纯求和无复用，分块收益有限
  • 大工作集下 TLB 是残留瓶颈
