Jacobi 五点 stencil：二维分块

1024×1024 网格 = 4MB —— 按 32 行分块，让三行数据留在 L1。

原始英文标题：ECE Lab — 2D Jacobi Stencil Cache Blocking

题面

本题复现了计算机体系结构高年级课程中经典的缓存优化实验：对 1024×1024 网格做一次 Jacobi 迭代。

基线结果正确，但它在热循环中流式扫过巨大的二维数组，几乎没有考虑缓存复用。

请重写内核，在保持数值结果一致的前提下改善 L1 与 L2 中的局部性。行分块、指针外提等都是可行手段。

任务
实现 void solve(const float *in, float *out, int n)，在 n×n 行优先网格上完成一次五点 Jacobi 更新。边界单元原样复制，内部单元设为 0.5*center + 0.125*(north + south + west + east)。

约束

  • 评测中 n = 1024
  • 边界单元必须与输入逐位一致
  • 内部更新公式必须保持数值等价
  • 不允许多线程
  • 允许 SIMD（非必需）

示例

输入1024×1024 行优先 float 网格
输出一次 Jacobi 迭代后的网格

优化报告


维度内容


核心瓶颈跨行访问的缓存复用


一句话思路1024×1024 网格 = 4MB —— 按 32 行分块，让三行数据留在 L1。


报告摘要按 32 行分块，块内为每行维护 north/center/south 三个行指针，并做 4 路展开。这样三行的工作集约 12KB，稳定留在 L1 中，上下行在相邻行之间被复用。





瓶颈定位
网格 1024×1024×4B = 4MB，远超 L2；朴素按行扫描时，每一行会被读取三次（作为 north、center、south）。
若三次读取之间该行已被挤出缓存，等效访存量就是 12MB 而非 4MB。
此外每次迭代要计算 5 个地址（idx-n、idx+n、idx-1、idx+1、idx），整数运算开销显著。
优化思路
行分块：以 TILE_ROWS=32 为一块，块内连续处理 32 行。此时活跃数据只有 3 行 × 4KB = 12KB，轻松驻留 L1。
三指针外提：在行循环内计算一次 north/center/south 行首指针，内层 x 循环只做 center[x] 这样的偏移访问。
4 路展开：一次迭代算 4 个输出单元，5 个输入值的乘加彼此独立。
关键改动
先把首行与末行整体复制（边界），内部区域单独处理，避免在热循环里做 if (y==0 || y==n-1) 判断。
行循环内只做一次乘法得到行首地址，把 y*n 从内层循环彻底消除。
展开时 x <= n-5 保证 center[x+4] 不越到下一行。
为什么更快
上下行复用：处理第 y 行时的 north 就是处理第 y-1 行时的 center，已经在 L1 里，省去一次内存读取。
等效访存量从 12MB 降到接近 4MB，L1 MPKI 与 LLC MPKI 同时下降。
指针外提与展开把每单元的地址计算从 5 次降到约 0.25 次。
常见误区
分块行数随意取：太小则块间切换开销大，太大则三行工作集超出 L1；32 行对应约 12KB，是 32KB L1 下的稳妥取值。
时间分块（沿时间维做多轮迭代的分块）在只做一次迭代时无效 —— 本题只迭代一次，因此只能做空间分块。
边界判断放进热循环：应像参考实现那样把边界整体外提处理。



要点速记
  • 32 行空间分块
  • north/center/south 三指针外提
  • 边界外提 + 4 路展开


常见误区与边界条件
  • 分块行数需匹配 L1 容量
  • 只迭代一次时时间分块无效
