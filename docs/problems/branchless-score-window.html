区间计分：用无符号技巧消除分支

一次比较同时判断上下界 —— 负数回绕成巨大的无符号数。

原始英文标题：Score Window — Remove Unpredictable Branches

题面

一个计分循环只累加落在目标区间内的值。基线对每个元素使用两层嵌套分支。

当输入分数大致均匀分布时，这些分支变得难以预测，损害前端吞吐。

请重写循环，在保持结果精确的前提下让热路径变得高度可预测，最好彻底无分支。

任务
实现 long solve(int *scores, int n)，返回所有落在闭区间 [50, 200] 内的 scores[i] 之和。

约束

  • scores[i] 为 0..255 范围内的整数
  • 不允许多线程
  • 允许 SIMD
  • 结果必须精确

示例

输入scores = 均匀分布在 0..255 的整数数组
输出所有 [50, 200] 区间内元素之和
说明利用无符号回绕：(unsigned)(s - 50) 在 s < 50 时会变成一个巨大的无符号数，因此一次 <= 150U 就能同时排除下界与上界。

优化报告


维度内容


核心瓶颈不可预测分支


一句话思路一次比较同时判断上下界 —— 负数回绕成巨大的无符号数。


报告摘要把两层嵌套 if 压缩为一次无符号比较：(unsigned)(scores[i] - 50) <= 150U，再用布尔值转整数做乘法完成条件累加。





瓶颈定位
基线对每个元素做两次判断：s >= 50 与 s <= 200，分支数翻倍。
分数在 0..255 均匀分布时，落在 [50,200] 内的概率约 59%，处于最难预测的概率区间。
更糟的是，分支还阻止了编译器对该循环做向量化。
优化思路
经典的无符号区间技巧：要判断 lo <= x <= hi，只需计算 (unsigned)(x - lo) <= (unsigned)(hi - lo)。
原理：当 x < lo 时，x - lo 为负数，转成无符号后会回绕成一个巨大的值，自然被 <= 判否。
把布尔结果 (window <= 150U) 直接当作 0/1 参与乘法：total += (long)(cond) * scores[i]。
关键改动
unsigned int window = (unsigned int)(scores[i] - 50); —— 关键就在强制转成无符号。
total += (long)(window <= 150U) * scores[i]; —— 比较结果 0/1 直接作为乘数。
循环体内不再有任何跳转指令。
为什么更快
Branch MPKI 降到接近 0，不再有流水线清空。
无分支的直线代码让编译器可以安全向量化，一次处理多个元素。
代价是无论是否命中区间都要做一次乘法 —— 当分支高度可预测时（例如 99% 命中），这种写法反而可能更慢。
常见误区
忘记无符号转换：若 window 声明为 int，负数不会回绕，判断就错了。
溢出风险：x - lo 本身在有符号域的溢出是未定义行为，务必先确认 x、lo 的取值范围。
认为无分支永远更快：无分支把"条件执行"变成"总是执行"，只有当分支误预测代价高于多做的算术时才划算。



要点速记
  • 无符号回绕实现一次比较定区间
  • 布尔转整数做条件累加
  • 为向量化创造条件


常见误区与边界条件
  • 必须确保无符号转换
  • 分支可预测时反而可能变慢
