SAXPY：解锁自动向量化

把循环写成规整形式，让编译器放心生成 SIMD。

原始英文标题：SAXPY — Unlock Auto-Vectorization

题面

在大规模 float 数组上计算经典的 SAXPY 更新 y[i] = a*x[i] + y[i]。基线结果正确但刻意写得保守。

请把循环重写成规整、对向量化友好的形式，让编译器与乱序核能榨出更多吞吐。

这是从 ILP 思维过渡到 SIMD 风格优化的实用桥梁 —— 即便不写 intrinsics。

任务
实现 void solve(float a, const float *x, float *y, int n)，用 a*x[i] + y[i] 更新 y 的全部 n 个元素。

约束

  • n = 262144（评测中固定）
  • 不允许多线程
  • 不允许外部库
  • 不要求 SIMD intrinsics
  • 浮点校验和容差：1e-4

优化报告


维度内容


核心瓶颈未向量化 / 循环开销


一句话思路把循环写成规整形式，让编译器放心生成 SIMD。


报告摘要把循环改写成无临时变量、步长为 8 的规整展开形式，消除一切让编译器犹豫的因素（别名、复杂控制流、逐元素临时量），从而触发自动向量化。





瓶颈定位
每元素只做 1 次乘 + 1 次加 + 2 次访存，是典型的访存受限（memory-bound）负载。
基线的 float xi = x[i]; float yi = y[i]; y[i] = yi + a*xi; 引入了额外的寄存器拷贝，也让数据流对编译器不够直观。
标量实现下，循环控制指令（比较、自增、跳转）占比可观。
优化思路
写成最直白的 y[i] = a * x[i] + y[i];，去掉中间临时变量。
8 路展开：一次迭代处理 8 个元素，给编译器明确的"可成组处理"信号，同时摊薄循环开销。
确保没有别名歧义：x 与 y 是不同数组，若有重叠顾虑可用 restrict 明确告知编译器。
关键改动
主循环 for (; i <= n - 8; i += 8)，体内 8 行独立的 y[i+k] = a*x[i+k] + y[i+k];。
尾部循环处理余数。
全程无分支、无函数调用、无指针别名歧义。
为什么更快
编译器把 8 行语句打包成若干条向量乘加指令，退休指令数大幅下降。
8 次迭代共享一次比较与跳转，前端压力显著降低。
由于是访存受限，IPC 的提升主要来自"同样周期内完成更多元素"，而非计算单元被填满。
常见误区
以为展开就等于向量化：展开只是为向量化创造条件，是否真生成 SIMD 要看编译器报告（-fopt-info-vec）。
忽略别名：若编译器无法证明 x、y 不重叠，它会生成运行时检查或干脆放弃向量化；此时 restrict 是关键。
访存受限时向量化收益有限：本题瓶颈在带宽，把 SIMD 宽度再翻倍也不会线性提速。



要点速记
  • 去掉临时变量让数据流清晰
  • 8 路展开 + 无分支
  • 必要时用 restrict 消除别名顾虑


常见误区与边界条件
  • 访存受限时收益有天花板
  • 展开不等于向量化
