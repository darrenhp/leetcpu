指针追逐：恢复内存级并行

一条链表是串行的 N 次失效；8 条链表交错遍历，就变成 8 路并行失效。

原始英文标题：Pointer Chasing — Recover Memory Parallelism

题面

需要对 8 条独立链表中存储的值求和，每条链表含 125,000 个节点。

基线实现先走完一条链表再走下一条，形成一条很长的串行缓存失效链，CPU 常常空等内存。

请改变遍历顺序，让不同链表的失效能够相互重叠，从而让核心利用更高的内存级并行度。

任务
实现 long solve(Node **heads, int num_lists)，每个节点恰好访问一次并返回总和，同时在各链表间交错推进以暴露彼此独立的访存失效。

约束

  • 输入以 8 个链表头指针给出
  • 每个节点必须恰好处理一次
  • 不允许多线程
  • 允许改变跨链表的遍历顺序

示例

输入heads = 8 个链表头，每链 125,000 个节点
输出所有节点 val 之和
说明顺序遍历时，下一个节点地址必须等当前节点载入后才能得到 —— 这是最典型的一类串行依赖访存。

优化报告


维度内容


核心瓶颈内存级并行（MLP）不足


一句话思路一条链表是串行的 N 次失效；8 条链表交错遍历，就变成 8 路并行失效。


报告摘要把"逐链深度优先"改成"跨链广度交错"：维护 8 个游标，每轮各向前走一步。于是同一时刻有 8 个彼此独立的访存请求在飞行中，MLP 从 1 提升到 8。





瓶颈定位
p = p->next 意味着下一次访存的地址来自上一次访存的结果 —— 完全串行，无法重叠。
单条链表遍历时，CPU 每个周期都在等 200 周期的内存延迟，IPC 被压到 0.1 量级。
这类负载既不受限于带宽，也不受限于计算，纯粹受限于"并发请求数"。
优化思路
8 条链表彼此独立，遍历第 3 条的节点不需要等待第 1 条的任何结果。
用 active[8] 保存 8 个当前游标，外层 while 每轮对 8 条链各前进一步。
于是在任意时刻，最多可以有 8 个 cache miss 同时在飞行中，等效延迟降低约 8 倍。
关键改动
把嵌套 for 改成 while (remaining > 0) + 内层 for 扫描 8 个游标的双层结构。
每轮重新统计 remaining，遇到空指针则跳过，保证所有链表走完后循环自然终止。
sum += p->val 仍是串行加法，但整数加法可以流水执行，不是瓶颈。
为什么更快
并发访存数从 1 提升到 8，同样的 200 周期延迟被 8 个请求共享，等效访存延迟大幅下降。
LLC MPKI 不一定下降（失效次数没变），但平均失效延迟显著下降 —— 这正是 MLP 优化的典型特征。
IPC 提升来自"不再空等"，而非指令数减少。
常见误区
以为要减少 cache miss：本优化不改变失效次数，只改变失效是否重叠。看指标时应关注平均延迟而非 MPKI。
交错路数越多越好？超过乱序窗口与 MSHR（失效状态保持寄存器）数量后，多余的请求只会排队，不再带来收益。
链表长度不一致时，短链走完后会留下空转的游标，需在实现里正确跳过。



要点速记
  • 串行失效 → 并行失效
  • MLP 是独立于带宽的优化维度
  • 关注平均失效延迟而非 MPKI


常见误区与边界条件
  • 并发度受 MSHR 数量限制
  • 链表长度不齐时需处理空游标
