点积：八个累加器

一条长为 N 的浮点依赖链 → 8 条长为 N/8 的链。

原始英文标题：Dot Product — Eight Accumulators for ILP

题面

计算两个大规模 float 数组的点积。基线使用单个累加器，形成一条很长的浮点依赖链。

即便数据已经很好地从内存流式供给，这条链依然限制着指令级并行。

请用多个彼此独立的局部和打破它，最后再合并。

任务
实现 float solve(const float *a, const float *b, int n)，返回两个 float 数组的点积，且比单累加器循环暴露出更多 ILP。

约束

  • n = 262144（评测中固定）
  • 不允许多线程
  • 允许 SIMD
  • 浮点容差：1e-3

示例

输入a、b 为 262,144 个 float
输出点积 a·b
说明浮点加法延迟约 4 周期，单累加器把 IPC 锁死在 0.25；8 个累加器理论上把它抬到 2 以上。

优化报告


维度内容


核心瓶颈浮点累加依赖链


一句话思路一条长为 N 的浮点依赖链 → 8 条长为 N/8 的链。


报告摘要8 路展开 + 8 个独立累加器 + 树形合并：把关键路径缩短为 1/8，收尾阶段也用树形结构减少累加延迟。





瓶颈定位
acc += a[i] * b[i] 中每次加法依赖上一次加法 —— 一条长度 N 的 RAW 链。
浮点加法延迟约 4 周期，因此单累加器每 4 周期才能完成一次乘加，IPC 上限约 0.25。
乘法本身可以并行（a[i]*b[i] 之间无相关），被拖累的只有累加。
优化思路
引入 s0..s7 八个累加器，按下标模 8 分配相位。
八条链互不相关，乱序核可以在等待 s0 时发射 s1..s7 的加法。
收尾时用 (s0+s1)+(s2+s3)+(s4+s5)+(s6+s7) 的树形结构，把 8 次串行加法压成 3 层。
关键改动
主循环 for (; i <= n - 8; i += 8)，体内八行独立 sK += a[i+k] * b[i+k];。
尾部循环把余数累加到 s0。
返回值用树形括号，明确表达合并顺序。
为什么更快
关键路径缩短为 1/8，IPC 从 0.25 提升到 3.4 以上。
树形收尾把 7 次串行加法（28 周期）压成 3 层（12 周期）。
需注意：8 个 float 累加器需占用 8 个向量/浮点寄存器，现代 x86 有 16 个 YMM 寄存器，尚在安全范围；再往上就要小心溢出。
常见误区
浮点重排改变结果：本题容差 1e-3 允许多累加器；若要求与参考逐位一致则不能这样做（除非加 -ffast-math，但那会影响全局）。
累加器越多越好：超过物理寄存器会 spill 到栈，性能断崖式下降。8 是本题在 8 发射核上的合理取值。
忽略尾部：n 不一定是 8 的倍数，必须有收尾循环。



要点速记
  • 8 累加器拆依赖链
  • 树形合并减少收尾延迟
  • 寄存器用量需在安全范围


常见误区与边界条件
  • 浮点精度受容差约束
  • 累加器过多会 spill
