13 中等 ILP 与流水线 ILP / 流水线 · GShare BP · 4-wide OoO · 32KB L1

直方图：打断写依赖链

相邻元素撞进同一个桶时会串行 —— 用 4 份部分直方图隔开它们。

原始英文标题：Histogram — Break Write Dependency Chains

题面

用 200 万个随机字节填充 256 桶的直方图。基线对每个元素执行 hist[arr[i]]++。

当连续两个元素落在同一个桶时，第二次自增必须等第一次完成 —— 这是一条写后写依赖链，会让流水线停顿。

请并行计算若干份彼此独立的局部直方图，最后再合并，从而打断这些链。

任务
实现 void solve(const unsigned char *arr, int n, unsigned int *hist)，统计每个字节值 0–255 的出现次数（hist[] 进入时已清零），使用交错的局部直方图减少写依赖停顿。

约束

  • n = 2,000,000（固定）
  • 调用前 hist[] 已清零
  • hist[i] 必须与参考计数完全一致
  • 不允许多线程
  • 允许 SIMD

示例

输入arr = 2,000,000 个 0–255 的随机字节
输出256 个桶的精确计数
说明桶只有 256 个（1KB），随机数据下相邻元素撞桶概率约 1/256，看似不高，但在 200 万次迭代中会造成大量零星的串行停顿。

优化报告


维度内容


核心瓶颈写后写（WAW）依赖


一句话思路相邻元素撞进同一个桶时会串行 —— 用 4 份部分直方图隔开它们。


报告摘要维护 4 份独立的 256 桶局部直方图，让相邻 4 个元素分别写入不同数组，从而消除写后写冲突；最后把 4 份结果逐桶相加。





瓶颈定位
hist[arr[i]]++ 是一次读-改-写。当 arr[i] == arr[i+1] 时，第二次自增必须等第一次的写完成 —— 这就是写后写（WAW）相关。
无序执行无法绕过它：乱序核必须保证对同一地址的访问维持程序顺序。
单份 1KB 的直方图常驻 L1，带宽不是问题；瓶颈纯粹是这些零星但频繁的依赖停顿。
优化思路
引入 h0/h1/h2/h3 四份直方图，第 i 个元素按 i % 4 写入对应的一份。
相邻 4 个元素必然写入不同数组，彼此之间没有地址冲突，可以完全并行。
只在相隔 4 个元素之间才可能撞桶，冲突概率从 1/256 降到约 1/256⁴ 量级（对同一份数组而言间隔被拉开 4 倍）。
关键改动
4 路展开，四行 hX[arr[i+k]]++ 写在同一个循环体内。
四份数组各 1KB，合计 4KB，仍然稳稳驻留 L1。
收尾阶段 hist[j] = h0[j]+h1[j]+h2[j]+h3[j]，只有 256 次，成本可忽略。
为什么更快
写依赖链被打断，自增操作可以流水执行，IPC 明显提升。
L1D 平均延迟下降：不再需要等待前一次对同一地址的写完成。
代价是 4KB 栈空间与 256 次合并 —— 相对于 200 万次迭代可以忽略。
常见误区
份数越多越好？每份 1KB，8 份就是 8KB，再乘以更宽的展开会开始挤占 L1；通常 4 份是甜点。
忘记清零：四份局部直方图若声明在栈上必须用 = {0} 初始化，否则结果全错。
忽略溢出：200 万 / 256 ≈ 7812，unsigned int 足够；但若数据规模更大需换用更宽的类型。



要点速记
  • 多份局部直方图消除 WAW 冲突
  • 总容量仍驻留 L1
  • 合并成本可忽略


常见误区与边界条件
  • 份数过多会挤占 L1
  • 必须显式初始化为 0
