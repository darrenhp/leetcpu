掩码 SAXPY：去分支换取吞吐

mask 为 0/1 —— 直接把它当乘数，分支就消失了。

原始英文标题：Masked SAXPY — Remove Branches, Unlock Throughput

题面

执行带掩码的 SAXPY 更新：若 mask[i] 为 1 则 y[i] = a*x[i] + y[i]，否则 y[i] 保持不变。

基线对每个元素使用一次分支。掩码大致 50/50 时，该分支难以预测，也让热循环对向量化不友好。

请重写循环，在保持结果精确的前提下做到无分支且面向吞吐。

任务
实现 void solve(float a, const float *x, float *y, const unsigned char *mask, int n)，精确执行掩码 SAXPY 更新。

约束

  • n = 262144（评测中固定）
  • mask[i] 取值只能为 0 或 1
  • 不允许多线程
  • 允许 SIMD
  • 浮点容差：1e-4

示例

输入x、y 为 262,144 个 float；mask 为 0/1 字节数组
输出按掩码更新后的 y
说明当 mask 为 0 时 y[i] += (a*x[i]) * 0.0f 等价于加零 —— 除 -0.0 与 NaN 等极端情形外与不更新等价。

优化报告


维度内容


核心瓶颈不可预测分支 + 阻碍向量化


一句话思路mask 为 0/1 —— 直接把它当乘数，分支就消失了。


报告摘要把 if (mask[i]) 改写成 y[i] += (a * x[i]) * (float)mask[i];，用一次乘法实现"条件执行"，再叠加 8 路展开。





瓶颈定位
掩码 50/50 时分支预测器退化为抛硬币，Branch MPKI 可达数十。
分支还把循环切成"每次迭代可能跳过工作"的形式，编译器无法安全向量化。
结果是双重损失：既付了误预测的代价，又拿不到 SIMD 的收益。
优化思路
mask 只有 0/1 两个取值 —— 直接把它转成 float 作为乘数：mask ? 1.0f : 0.0f。
于是 y[i] += (a * x[i]) * (float)mask[i] 在 mask=0 时等价于加 0，在 mask=1 时等价于正常更新。
无分支的直线代码可以被安全地向量化。
关键改动
删除 if (mask[i])，改为 8 行 y[i+k] += (a * x[i+k]) * (float)mask[i+k];。
8 路展开，尾部循环处理余数。
把 y[i] = a*x[i] + y[i] 改成 y[i] += ... 形式，配合乘 0 实现"保持不变"。
为什么更快
Branch MPKI 降到接近 0，前端不再被误预测打断。
向量化后每周期处理多个元素，IPC 提升到 3 以上。
代价：所有元素都要做乘法与加法，包括 mask=0 的那些 —— 这是用"多做算术"换"不赌分支"。
常见误区
认为无分支永远更快：若掩码 99% 为 0，带分支的版本会跳过大部分工作，反而更快。判断是否划算要看 分支误预测率 × 15 周期 与 多做的算术周期数 谁更大。
-0.0 与 NaN 的边角：加 0.0 会把 -0.0 变成 +0.0，也会传播 NaN；本题容差 1e-4 下可接受，但对逐位一致的场景要谨慎。
忘记 (float) 转换：若 mask 是 unsigned char，需确保转换到 float 而非整数乘。



要点速记
  • 掩码当乘数实现条件执行
  • 为向量化扫清障碍
  • 8 路展开


常见误区与边界条件
  • 掩码高度偏斜时分支版本更快
  • -0.0 / NaN 语义差异
