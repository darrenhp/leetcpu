09 中等 缓存层次 缓存局部性 · ChampSim · 32KB L1D · stencil trace

图像模糊：让工作集留在缓存里

水平 3-tap 卷积 —— 收益主要来自指针外提与展开。

原始英文标题：Image Blur — Tile the Working Set

题面

对 512×512 图像做水平 3-tap 模糊。每像素的算术量很小，因此性能主要取决于能否让行数据保持缓存热、并按顺序写出结果。

请用指针运算、分块、展开或类似的循环改进重写起始代码，使工作集保持缓存友好。

任务
实现 void solve(float *in, float *out, int width, int height)，使每个非边缘输出像素等于其左、中、右三邻居的平均，边缘像素原样复制。

约束

  • width = height = 512
  • 边缘像素必须原样复制
  • 不允许多线程
  • 允许 SIMD

示例

输入512×512 浮点图像
输出水平 3-tap 模糊后的图像，边缘保持不变
说明单张图像 512×512×4B = 1MB，超过 L1 但能进 L2；因此按行分块能让输入行在 L1 中复用。

优化报告


维度内容


核心瓶颈缓存行复用与循环开销


一句话思路水平 3-tap 卷积 —— 收益主要来自指针外提与展开。


报告摘要按行分块（32 行一块）+ 行指针外提 + 4 路展开。但要诚实说明：水平 1D 卷积本身已是顺序访问，真正的收益来自展开与指针优化，分块在这里只是次要贡献。





瓶颈定位
基线已经是行优先顺序访问，空间局部性本身不差。
真正的浪费在两处：①每次迭代都要重算 row + x 与三次数组下标；②每次迭代只有一次乘加，循环控制指令占比过高。
图像共 1MB，超出 L1（32KB），因此仍存在行被反复从 L2 读取的压力。
优化思路
指针外提：把 in + row、out + row 提到行循环外，内层直接用 src[x]、dst[x]，消除重复的地址计算。
4 路展开：一次迭代写 4 个输出像素，摊薄比较与跳转开销，同时让 4 组乘加彼此独立。
按行分块：以 32 行为一块遍历，让输入行在块内保持缓存热（对二维 stencil 收益更明显）。
关键改动
外层 y0 以 TILE_ROWS=32 步进，内层遍历块内各行。
行首 dst[0] = src[0]、行尾 dst[width-1] = src[width-1] 单独处理，中间部分可安全展开。
主循环条件 x <= width - 5 保证展开时不越界，余数由收尾循环处理。
为什么更快 —— 也说说局限
指针外提减少了约 3 次整数加法/迭代；展开把循环控制指令降为 1/4。
乘加之间彼此独立，乱序核可以重叠执行，IPC 提升明显。
必须承认：对纯水平 stencil，分块的贡献有限 —— 因为每行只被读一次（3 个邻居在行内，不跨行复用）。分块的真正舞台是第 11 题那种跨行的 2D 五点 stencil。
常见误区
盲目加分块：若数据没有跨块复用，分块只会增加代码复杂度。
展开越宽越好：过宽会导致寄存器溢出并撑大热循环，反而伤害指令缓存。
忽略边缘：展开时必须保证 x+4 不越界，否则会读到下一行的开头。



要点速记
  • 指针外提消除重复地址计算
  • 4 路展开摊薄循环开销
  • 分块对水平 stencil 收益有限


常见误区与边界条件
  • 展开过宽引发寄存器溢出
  • 边缘像素需单独处理
